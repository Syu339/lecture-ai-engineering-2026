# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：第1回の素のLLMは、学習済みの知識だけを使って回答するため、講座固有の情報については不正確な回答を生成する可能性がある。一方、エージェントは用語集検索などの外部ツールを利用できるため、講座の情報に基づいた回答が可能になる。今回の実験では、用語集から「量子化」に関する復習問題を生成できた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：make_quiz({'lecture': 2})
第2回の復習問題を求めたところ、エージェントが自動的に make_quiz を選択し、引数 lecture=2 を渡して実行した。結果として「量子化とは何ですか？」という問題と解答が返された。
- 1つの質問での LLM 呼び出し回数（`requests`）：2回（requests=2）。1回目のLLM呼び出しでツールの使用を判断し、make_quiz を実行した後、2回目のLLM呼び出しでツールの結果をもとに最終回答を生成した。
- 追加したツールと、docstring に書いた説明：追加したツールは make_quiz(lecture: int) -> str。指定した講義回の用語集から用語をランダムに1つ選び、「Xとは何ですか？」という復習問題とその解答をJSON形式で返す。docstringには、復習問題やクイズを求められた際に使用すること、引数 lecture には講義回を1始まりの整数で指定すること、問題と解答を返すことを記載した。

## 宿題

- 取り組んだレベル：基礎
- やったこと：学習支援エージェントの INSTRUCTIONS と各ツールの docstring を変更し、同じ質問「第2回の復習問題を1問出してください」で回答とツール呼び出しを比較した。特に、復習問題にヒントと学習ポイントを付けるよう指示し、2段階で指示文を改善した。
- 結果：3回の実験すべてで make_quiz(lecture=2) が呼び出され、LLM呼び出し回数は2回、ツール呼び出し回数は1回だった。最初は問題のみが提示されたが、出力形式を具体的に指定した結果、ヒントと学習ポイントが追加された。ただし、関連講義の表示は省略された。
- 気づき・疑問：ツールの選択が同じでも、指示文の具体性によって最終回答が変化することが分かった。一方、明示した指示がすべて守られるわけではなく、ヒントが正解に近すぎる場合もあった。回答形式の安定性やヒントの適切さを高めるには、プロンプトの改善だけで十分なのか、プログラム側で出力形式を制御する必要があるのか疑問に感じた。
